Série 3 — Sur machine

Ex 1 — Le tour de magie binaire

Correction

Entre 0 et 31, 5 bits suffisent → 5 cartes. La carte k contient tous les nombres dont le bit k vaut 1 ; son premier nombre est 2ᵏ (1, 2, 4, 8, 16). Alice additionne les premiers nombres des cartes citées : 1ère et 5e carte → 1 + 16 = 17.

En base 3, de 0 à 26 = 3³ − 1 → 3 chiffres ternaires. Chaque chiffre vaut 0, 1 ou 2 : il faut une carte « chiffre = 1 » et une carte « chiffre = 2 » par position, soit 6 cartes.

/* conversion en base 3 (affiche les chiffres à l'envers) */
int n;
scanf("%d", &n);
while (n > 0) {
    printf("%d", n % 3);
    n = n / 3;
}

Ex 2 — La base Zeck (Fibonacci)

Correction
  • F2…F9 = 1, 2, 3, 5, 8, 13, 21, 34.
  • 11 = 8 + 3 = F6 + F4 → (10100)Zeck ; 47 = 34 + 13 = F9 + F7 → (10100000)Zeck (méthode gloutonne : on prend le plus grand F ≤ N, on recommence avec le reste).
  • (1010001)Zeck = F8 + F6 + F2 = 21 + 8 + 1 = 30 ; (1000010001)Zeck = F11 + F6 + F2 = 89 + 8 + 1 = 98.

Ex 3 et 4 — Pièges des float

Correction
  • Ex 3 : x = 100000000000000 (10¹⁴) n'est pas représentable exactement avec 24 bits de mantisse : ligne 5 affiche 100000000376832.000000. y = x − 1 donne la même valeur (1 est sous la précision). Donc while (x > 0) x = x − 1; ne fait jamais diminuer x : boucle infinie, la ligne 10 n'est jamais atteinte.
  • Ex 4 : 0,1 n'a pas d'écriture binaire finie → x vaut ≈ 0,100000001. Après 100 additions, y ≈ 10,0000019 ≠ 10 → y != 10 reste vrai → boucle infinie. Règle : ne jamais tester l'égalité de deux réels ; utiliser y < 10.

Ex 2 — Décoder de l'UTF-8 à la main

Correction
  • Version 1 : français. c3 a9 = 11000011 10101001 → 00011101001 = U+00E9 = é (233) ; e2 80 99 = 11100010 10000000 10011001 → U+2019 = ’ (apostrophe typographique, 8217). Le reste est de l'ASCII (1 octet commençant par 0).
  • Version 2 : octets d8/d9 = 2 octets → U+062F, U+0648… : arabe.
  • Version 3 : e8 b3 87 = 3 octets → U+8CC7 (資) … : chinois (traditionnel).
  • Version 4 : U+C815 (정) … : coréen.
  • Version 5 : U+60C5 (情), puis U+30B3 (コ, katakana) … : japonais.

Le programme qui affiche octet par octet avec %c casse les caractères multi-octets : il faut regrouper les octets selon leur en-tête.

Algorithme de décodage UTF-8 (fin de l'Ex 2) 
while (i < taille) {
    unsigned char o = TabChar[i];
    int code, nb;
    if (o < 0x80)      { code = o;        nb = 0; }   /* 0xxxxxxx */
    else if (o < 0xE0) { code = o & 0x1F; nb = 1; }   /* 110xxxxx : garde 5 bits */
    else if (o < 0xF0) { code = o & 0x0F; nb = 2; }   /* 1110xxxx : garde 4 bits */
    else               { code = o & 0x07; nb = 3; }   /* 11110xxx : garde 3 bits */
    i++;
    while (nb > 0) {                     /* octets de suite 10xxxxxx */
        code = code * 64 + (TabChar[i] & 0x3F);    /* décale de 6 bits, ajoute 6 bits */
        i++; nb--;
    }
    printf("%d ", code);
}

Ex 12 — chiffre de César 
/* décalage d : lettres et chiffres décalés circulairement, le reste inchangé */
if (c >= 'A' && c <= 'Z') c = 'A' + (c - 'A' + d) % 26;
else if (c >= 'a' && c <= 'z') c = 'a' + (c - 'a' + d) % 26;

/* déchiffrer = décaler de 26 - d (lettres) et 10 - d (chiffres) */

Entraînement CM6 — détection et correction

A. Bits de parité

Ajouter un bit de parité paire à 1010001, 1111000, 0000001. Le mot 10100011 a été reçu en 10010011 : l'erreur est-elle détectée ?
Correction

1010001 (3 uns) → 10100011 ; 1111000 (4 uns) → 11110000 ; 0000001 (1 un) → 00000011.

10010011 contient 4 uns (pair) → non détectée : deux bits ont changé, la parité est conservée.

B. Distance de Hamming

Calculer d(1011101, 1001001) et d(1100110, 0110011).
Correction

XOR bit à bit puis compter les 1 : 1011101 ⊕ 1001001 = 0010100 → 2 ; 1100110 ⊕ 0110011 = 1010101 → 4.

E. Code de Hamming 7-4

1) Coder 1101 et 0110. 2) On reçoit 1010011, puis 0111100. Y a-t-il une erreur ? Laquelle ?
Correction 1)

Rappel : positions 7 6 5 4 3 2 1 = D3 D2 D1 C2 D0 C1 C0 ; C2 → {7,6,5,4}, C1 → {7,6,3,2}, C0 → {7,5,3,1}.

  • 1101 : D3=1 D2=1 D1=0 D0=1 → C2 = parité(1,1,0) = 0 ; C1 = parité(1,1,1) = 1 ; C0 = parité(1,0,1) = 0 → 1100110.
  • 0110 : D3=0 D2=1 D1=1 D0=0 → C2 = 0 ; C1 = 1 ; C0 = 1 → 0110011.
Correction 2)
  • 1010011 : groupe {7,6,5,4} = 1+0+1+0 pair → 0 ; {7,6,3,2} = 1+0+0+1 pair → 0 ; {7,5,3,1} = 1+1+0+1 impair → 1. Syndrome 001 = 1 → le bit n°1 (C0) est faux → mot corrigé 1010010, message 1010.
  • 0111100 : {7,6,5,4} = 0+1+1+1 impair → 1 ; {7,6,3,2} = 0+1+1+0 pair → 0 ; {7,5,3,1} = 0+1+1+0 pair → 0. Syndrome 100 = 4 → bit n°4 (C2) faux → corrigé 0110100, message (positions 7, 6, 5, 3) 0111.
