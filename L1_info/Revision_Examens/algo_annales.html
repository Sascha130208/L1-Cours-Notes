Exercice 3 — facture de reprographie 2 + 4 pts

0,10 € la copie de 1 à 100 copies, 0,09 € de 101 à 300, 0,08 € au-delà. TVA = constante de 20 %. Q1 : arbre de décision binaire. Q2 : algorithme qui affiche la facture.
Correction Q1 — arbre

Variables : entier nb (nombre de copies) ; réel prixU, ht, tva, ttc ; constante réel TVA ← 0.20.

                 nb ≤ 100 ?
              vrai/        \faux
       prixU ← 0.10       nb ≤ 300 ?
                        vrai/     \faux
                 prixU ← 0.09   prixU ← 0.08

  ensuite : ht ← nb * prixU ; tva ← TVA * ht ; ttc ← ht + tva ; affichage
Correction Q2 — algorithme 
Algorithme Reprographie
constantes
    réel TVA ← 0.20 ;
variables
    entier nb ;
    réel prixU, ht, tva, ttc ;
début
    écrire "Combien de copies voulez-vous ? " ;
    lire nb ;
    tantque (nb < 1) faire                     // au moins 1 copie
        écrire "Nombre incorrect, recommencez : " ;
        lire nb ;
    fintantque
    si (nb ≤ 100) alors
        prixU ← 0.10 ;
    sinon
        si (nb ≤ 300) alors
            prixU ← 0.09 ;
        sinon
            prixU ← 0.08 ;
        finsi
    finsi
    ht ← nb * prixU ;
    tva ← TVA * ht ;

Exercice 4 — dépréciation d'une machine 4 + 4 pts

Une machine perd 10 % de sa valeur par an. Q1 : valeur après n années. Q2 : au bout de combien d'années aura-t-elle perdu 50 % de sa valeur ?
Correction Q1 
Algorithme Decote
variables
    réel prix, valeur ;
    entier n, i ;
début
    écrire "Quel est le prix d'achat de votre machine outil en € ? " ;
    lire prix ;
    écrire "Sur combien d'années souhaitez-vous calculer sa décote ? " ;
    lire n ;
    valeur ← prix ;
    pour (i allant de 1 à n pas 1) faire       // nombre de tours connu → pour
        valeur ← valeur * 0.9 ;                 // perdre 10 % = garder 90 %
    finpour
    écrire "Votre machine vaudra ", valeur, " € au bout de ", n, " ans" ;
fin

192 × 0,9³ = 139,968 ≈ 139,97 €.

Correction Q2 
Algorithme MoitieValeur
variables
    réel prix, valeur ;
    entier annees ;
début
    écrire "Quel est le prix d'achat de votre machine outil en € ? " ;
    lire prix ;
    valeur ← prix ;
    annees ← 0 ;
    tantque (valeur > prix / 2) faire          // nombre de tours inconnu → tantque
        valeur ← valeur * 0.9 ;
        annees ← annees + 1 ;
    fintantque
    écrire "La machine aura perdu 50 % de sa valeur au bout de ", annees, " ans" ;
fin

Résultat : 7 ans quel que soit le prix (0,9⁶ ≈ 0,53 > 0,5 et 0,9⁷ ≈ 0,48 ≤ 0,5). Attention : si prix ≤ 0 la boucle ne tourne pas ; on peut ajouter une saisie contrôlée prix > 0.

Q1 — à quoi servent les lignes 06 à 09 ?

C'est une saisie contrôlée : on redemande les trois entiers tant qu'on n'a pas D ≤ Val1 ≤ Val2.

Q2 — peut-on simplifier la ligne 06 ?

Oui : tantque ((D > Val1) ou (Val1 > Val2)) faire.

Justification : si D ≤ Val1 et Val1 ≤ Val2 alors forcément D ≤ Val2 (transitivité). Donc le test D > Val2 ne peut être vrai que si l'un des deux autres l'est déjà : il est inutile.

Elles affichent tous les multiples de D compris entre Val1 et Val2 (bornes incluses).

Exercice 2 — diviseurs 3 + 4 pts

On saisit x, y, z supposés triés (x ≤ y ≤ z). Afficher si x divise y et/ou z, et si y divise z. Si non triés : message d'erreur. Ex. : 3, 6, 18 → « 3 est diviseur de 6 et 18 », « 6 est diviseur de 18 ».
Correction Q1 — arbre de décision

Variables : entier x, y, z. On suppose les entiers strictement positifs (sinon mod 0).

                     (x ≤ y) et (y ≤ z) ?
                  faux/                 \vrai
     "erreur : non triés"           y mod x = 0 ?
                              vrai/                 \faux
                        z mod x = 0 ?             z mod x = 0 ?
                      vrai/      \faux          vrai/      \faux
            "x div. de y et z"  "x div. de y"  "x div. de z"   (rien)

          puis (dans la branche « triés ») :   z mod y = 0 ?
                                            vrai/      \faux
                                     "y div. de z"    (rien)
Correction Q2 — algorithme 
Algorithme Diviseurs
variables
    entier x, y, z ;
début
    écrire "Donnez trois entiers strictement positifs triés x ≤ y ≤ z :" ;
    lire x, y, z ;
    si ((x ≤ 0) ou (x > y) ou (y > z)) alors
        écrire "Erreur : les valeurs ne sont pas triées (ou x ≤ 0)" ;
    sinon
        si (y mod x = 0) alors
            si (z mod x = 0) alors
                écrire x, " est diviseur de ", y, " et ", z ;
            sinon
                écrire x, " est diviseur de ", y ;
            finsi
        sinon
            si (z mod x = 0) alors
                écrire x, " est diviseur de ", z ;
            finsi
        finsi
        si (z mod y = 0) alors
            écrire y, " est diviseur de ", z ;
        finsi
    finsi
fin

Test 3, 6, 21 : 6 mod 3 = 0 et 21 mod 3 = 0 → « 3 est diviseur de 6 et 21 » ; 21 mod 6 = 3 → rien d'autre ✔.

Exercice 3 — valeur « Mstar paire » 4 + 2 pts

Saisir NB jusqu'à ce qu'il soit positif. On multiplie les chiffres pairs ; si le résultat a plus d'un chiffre, on recommence. Ex. : 34651514 → 4×6×4 = 96 → 6. Mstar(34505678) = 0 (il y a un 0) et Mstar(35733979) = 0 (aucun chiffre pair).
Correction Q1 
Algorithme MstarPaire
variables
    entier NB, n, p, c ;
    booléen pairTrouve ;
début
    écrire "Donnez un entier positif :" ;
    lire NB ;
    tantque (NB < 0) faire                       // patron P1 : saisie contrôlée
        écrire "Erreur, donnez un entier positif :" ;
        lire NB ;
    fintantque
    n ← NB ;
    tantque (n ≥ 10) faire                       // tant qu'il y a plus d'un chiffre
        p ← 1 ;
        pairTrouve ← faux ;
        tantque (n > 0) faire                    // patron P2 : parcours des chiffres
            c ← n mod 10 ;
            si (c mod 2 = 0) alors
                p ← p * c ;
                pairTrouve ← vrai ;
            finsi
            n ← n div 10 ;
        fintantque
        si (non pairTrouve) alors                // aucun chiffre pair → 0
            p ← 0 ;
        finsi
        n ← p ;
    fintantque
    écrire "La valeur Mstar paire de ", NB, " vaut ", n ;
fin

Pourquoi le booléen ? Sans lui, un nombre sans chiffre pair donnerait p = 1 (valeur initiale), alors que l'énoncé veut 0.

Exercice 3 — nombres insolites 3 + 3 + 4 pts

n est insolite s'il est divisible par S = somme des carrés de ses chiffres et par P = produit des carrés de ses chiffres. Ex. : 11112 → S = 8, P = 4, et 11112 est divisible par 8 et par 4.

écrire "Donnez un entier strictement positif :" ;
lire n ;
tantque (n ≤ 0) faire
    écrire "Erreur, recommencez :" ;
    lire n ;
fintantque
Correction Q2 — afficher les chiffres 
copie ← n ;                      // on garde n intact pour la suite
tantque (copie > 0) faire
    écrire copie mod 10 ;
    copie ← copie div 10 ;
fintantque

(les chiffres s'affichent de droite à gauche : unités d'abord).

Correction Q3 — algorithme complet 
Algorithme Insolite
variables
    entier n, copie, c, S, P ;
début
    écrire "Donnez un entier strictement positif :" ;
    lire n ;
    tantque (n ≤ 0) faire
        écrire "Erreur, recommencez :" ;
        lire n ;
    fintantque
    S ← 0 ;                      // neutre de l'addition
    P ← 1 ;                      // neutre de la multiplication
    copie ← n ;
    tantque (copie > 0) faire
        c ← copie mod 10 ;
        S ← S + c * c ;
        P ← P * c * c ;
        copie ← copie div 10 ;
    fintantque
    // P = 0 si n contient un 0 : on teste P ≠ 0 AVANT de diviser (court-circuit du et)
    si ((P ≠ 0) et (n mod S = 0) et (n mod P = 0)) alors
        écrire n, " est un nombre insolite" ;
    sinon
        écrire n, " n'est pas un nombre insolite" ;
    finsi
fin

⭐ Examen terminal 2024-2025

⚠️ Le sujet le plus proche de ton examen C'est le seul sujet d'examen terminal disponible : il porte sur les fonctions et les tableaux. Cette année l'examen dure 1 h (contre 2 h en 2024) : attends-toi à un sujet plus court mais du même style.
Un entier > 0 est représenté par sa décomposition en facteurs premiers dans deux tableaux de 10 cases : Prem (les nombres premiers, croissants, 0 = case vide) et Puiss (les puissances). Ex. : 378 = 2¹·3³·7¹.

Q1 — valeur de Prem = [2,3,5,0…], Puiss = [3,1,1,0…] 1 pt

Correction

2³ × 3¹ × 5¹ = 8 × 3 × 5 = 120.

Q2 — fonction Puissance(a, b) 2,5 pts

Correction 
fonction avec retour entier Puissance(entier a, entier b)
variables
    entier i, res ;
début
    res ← 1 ;
    pour (i allant de 1 à b pas 1) faire
        res ← res * a ;
    finpour
    retourne res ;               // si b = 0, la boucle ne tourne pas : a⁰ = 1 ✔
fin

Q5 — fonction EstPremier(n) 2 pts

Correction 
fonction avec retour booléen EstPremier(entier n)
variables
    entier d ;
    booléen premier ;
début
    si (n < 2) alors                  // 0 et 1 ne sont pas premiers
        premier ← faux ;
    sinon
        premier ← vrai ;
        d ← 2 ;
        tantque ((d * d ≤ n) et premier) faire
            si (n mod d = 0) alors
                premier ← faux ;
            finsi
            d ← d + 1 ;
        fintantque
    finsi
    retourne premier ;
fin

On peut aussi tester d de 2 à n−1 : c'est juste plus lent. Il suffit d'aller jusqu'à √n : si n = d × e avec d ≤ e, alors d ≤ √n.

Q7 — fonction RechercheTab(T, long, x) 2 pts

Correction (recherche séquentielle) 
fonction avec retour entier RechercheTab(entier Tableau T, entier long, entier x)
variables
    entier i, pos ;
début
    pos ← -1 ;
    i ← 0 ;
    // tableau trié : inutile de continuer quand T[i] dépasse x
    tantque ((i < long) et (pos = -1) et (T[i] ≤ x)) faire
        si (T[i] = x) alors
            pos ← i ;
        finsi
        i ← i + 1 ;
    fintantque
    retourne pos ;
fin

Le court-circuit du et évite de lire T[long] (hors tableau) quand i = long.

Bonus : recherche dichotomique (plus rapide, possible car le tableau est trié) 
fonction avec retour entier RechercheTab(entier Tableau T, entier long, entier x)
variables
    entier deb, fin2, milieu, pos ;
début
    deb ← 0 ; fin2 ← long - 1 ; pos ← -1 ;
    tantque ((deb ≤ fin2) et (pos = -1)) faire
        milieu ← (deb + fin2) div 2 ;
        si (T[milieu] = x) alors
            pos ← milieu ;
        sinon
            si (T[milieu] < x) alors
                deb ← milieu + 1 ;
            sinon
                fin2 ← milieu - 1 ;
            finsi
        finsi
    fintantque
    retourne pos ;
fin

Q8 — fonction PGCD de deux nombres décomposés 3 pts

Exemple : 3⁴·5³·7²·11 et 5²·7³·13 → PGCD = 5²·7² = 1225.
Idée

Le PGCD contient les premiers communs aux deux nombres, chacun avec la plus petite des deux puissances.

Correction 
fonction avec retour entier PGCD(entier Tableau Prem1, entier Tableau Puiss1,
                                 entier Tableau Prem2, entier Tableau Puiss2)
variables
    entier i, n2, pos, e, res ;
début
    n2 ← 0 ;                                   // nombre de cases utiles de Prem2
    tantque ((n2 < 10) et (Prem2[n2] ≠ 0)) faire
        n2 ← n2 + 1 ;
    fintantque
    res ← 1 ;
    pour (i allant de 0 à 9 pas 1) faire
        si (Prem1[i] ≠ 0) alors
            pos ← RechercheTab(Prem2, n2, Prem1[i]) ;   // premier commun ?
            si (pos ≠ -1) alors
                si (Puiss1[i] < Puiss2[pos]) alors       // plus petite puissance
                    e ← Puiss1[i] ;
                sinon
                    e ← Puiss2[pos] ;
                finsi
                res ← res * Puissance(Prem1[i], e) ;
            finsi
        finsi
    finpour
    écrire res ;
    retourne res ;
fin

Pourquoi n2 ? Les 0 en fin de Prem2 cassent l'ordre croissant : on ne cherche que dans la partie remplie.
