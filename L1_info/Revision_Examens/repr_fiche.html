1. Bases de numération

Un système de numération = une base B + un ensemble ordonné de B chiffres. Le nombre (xn−1 … x1 x0)B vaut :

xn−1·Bn−1 + … + x2·B² + x1·B + x0

  • xn−1 = chiffre de poids fort (à gauche) ; x0 = chiffre de poids faible (à droite).
  • Bases utilisées : 2 (binaire, chiffres 0-1), 8 (octal, 0-7), 10, 16 (hexadécimal, 0-9 puis A=10 … F=15).
  • 0 et 1 s'écrivent pareil dans toutes les bases. Un chiffre doit être < B : (5783)₈ n'existe pas (8 n'est pas un chiffre octal) !

2. Les 4 méthodes de conversion

Méthode 1 — calcul de l'expression (base B → base 10)

(11101011)₂ = 128 + 64 + 32 + 8 + 2 + 1 = 235.   (A1C)₁₆ = 10·256 + 1·16 + 12 = 2588.

Méthode 2 — divisions successives (base 10 → base B)

On divise par B jusqu'à un quotient nul ; on lit les restes de bas en haut.

235 / 2 = 117 reste 1   ↑
117 / 2 =  58 reste 1   |
 58 / 2 =  29 reste 0   |   lire de bas en haut :
 29 / 2 =  14 reste 1   |   235 = (11101011)₂
 14 / 2 =   7 reste 0   |
  7 / 2 =   3 reste 1   |
  3 / 2 =   1 reste 1   |
  1 / 2 =   0 reste 1   |

Méthode 3 — table des puissances de 2 (base 10 → base 2)

On retire la plus grande puissance de 2 possible, et on recommence : 235 = 128 + 107 = 128 + 64 + 43 = 128+64+32+11 = 128+64+32+8+2+1 → bits 7,6,5,3,1,0 à 1 → 11101011.

Méthode 4 — regroupement de bits (base 2 ↔ 8 ou 16)

  • 16 = 2⁴ : 1 chiffre hexa = 4 bits. On groupe depuis la droite par 4.
  • 8 = 2³ : 1 chiffre octal = 3 bits. On groupe par 3.
  • Hexa → octal : passer par le binaire. (5D9E)₁₆ = 101 110 110 011 110 = (56636)₈.

(3A9B)₁₆ = 0011 1010 1001 1011 = (11101010011011)₂.   (10010111010)₂ = 100 1011 1010 = (4BA)₁₆.

3. Nombres à virgule

  • Base B → 10 : les chiffres après la virgule valent B⁻¹, B⁻², … : (110,11)₂ = 4+2+0,5+0,25 = 6,75 ; (110,11)₈ = 64+8+1/8+1/64 = 72,140625.
  • 10 → base 2 : partie entière par divisions ; partie décimale par multiplications successives par 2 : on garde la partie entière obtenue (0 ou 1) et on continue avec la partie décimale.
0,34375 × 2 = 0,6875  → 0
0,6875  × 2 = 1,375   → 1
0,375   × 2 = 0,75    → 0      lire de HAUT en bas :
0,75    × 2 = 1,5     → 1      0,34375 = (0,01011)₂
0,5     × 2 = 1,0     → 1      donc 64,34375 = (1000000,01011)₂
⚠️ Développement infini 0,1 ; 0,15 ; 0,3 ; 0,45 n'ont pas d'écriture binaire finie : (0,3)₁₀ = (0,0100110011…)₂ — le motif 1001 se répète. C'est la cause de la catastrophe du missile Patriot (TD2) et des boucles infinies avec des float.

10 → 16 : même méthode en multipliant par 16 : 0,25 × 16 = 4 → (35,25)₁₀ = (23,4)₁₆.

4. Opérations

  • Addition binaire : 0+0=0, 0+1=1, 1+1=10 (0, retenue 1), 1+1+1=11 (1, retenue 1).
  • Soustraction : 0−1 = 1 avec emprunt de 1 sur le rang suivant.
  • Hexa : on additionne en décimal chiffre par chiffre ; si ≥ 16 on retire 16 et on retient 1. Ex. F + 8 = 23 = 16 + 7 → 7 retenue 1.
  • Multiplication binaire : comme à la main, avec des décalages (multiplier par 2 = ajouter un 0 à droite).
  • Toujours vérifier en décimal.

6. Entiers non signés

  • Écriture binaire complétée à gauche par des 0. 98 sur un octet = 01100010.
  • Sur n bits : de 0 à 2ⁿ − 1. 1 octet : 0 → 255 ; 2 octets : 0 → 65 535 ; 4 octets : 0 → 4 294 967 295.
  • Dépassement de capacité : le résultat ne tient plus sur n bits, la retenue sortante est perdue. 200 + 100 = 300 = 1 0010 1100 → sur un octet il reste 00101100 = 44 (faux). C'est l'erreur d'Ariane 5 (accélération 300 codée sur 8 bits).

7. Entiers signés

Signe + valeur absolue

Le bit de poids fort = signe (0 → +, 1 → −), les autres = valeur absolue. Sur un octet : −9 = 1000 1001. Intervalle [−(2ⁿ⁻¹−1), +(2ⁿ⁻¹−1)] = [−127, 127]. Défauts : deux zéros (00000000 et 10000000) et l'addition ne marche pas directement (5 + (−9) donne n'importe quoi).

Complément à 1 (C1)

Pour −X, on inverse tous les bits de X. −9 = NON(00001001) = 11110110. Encore deux zéros.

⭐ Complément à 2 (C2) — la représentation utilisée par les ordinateurs

Méthode pour coder −X sur n bits
  1. écrire X en binaire sur n bits ;
  2. inverser tous les bits (C1) ;
  3. ajouter 1.
Astuce rapide : en partant de la droite, on recopie les bits jusqu'au premier 1 inclus, puis on inverse tous les autres.
−45 :  45 = 00101101  → C1 : 11010010 → +1 : 11010011
−64 :  64 = 01000000  → C1 : 10111111 → +1 : 11000000
 −1 :   1 = 00000001  → C1 : 11111110 → +1 : 11111111
  • Décoder un octet signé : s'il commence par 0 → positif, on lit normalement. S'il commence par 1 → négatif : on refait C2 pour obtenir la valeur absolue. 11011100 → C1 00100011 → +1 00100100 = 36 → −36. (Ou : valeur non signée − 256 = 220 − 256 = −36.)
  • Intervalle sur n bits : [−2ⁿ⁻¹, 2ⁿ⁻¹ − 1] → 1 octet : [−128, 127]. Un seul zéro.
  • La soustraction devient une addition : 5 − 9 = 5 + (−9). On ignore la retenue qui sort.
  • Dépassement : seulement quand on additionne deux nombres de même signe et que le résultat a le signe opposé. 100 + 120 = 220 > 127 → 11011100 = −36 (faux). −120 + (−45) = −165 < −128 → 01011011 = 91 (faux).

8. Virgule fixe

La virgule est à une place fixée une fois pour toutes. Format [5,3] sur un octet : 5 bits avant la virgule, 3 après.

  • 11000101 en [5,3] non signé = (11000,101)₂ = 16+8+0,5+0,125 = 24,625.
  • Pas (écart entre deux valeurs) : 2⁻³ = 0,125. Non signé : de 0 à 31,875. Signé (C2) : de −16 (10000000) à 15,875 (01111111).
  • Signé : on code la valeur comme un entier C2 sur 8 bits puis on divise par 2³ = 8. Ex. 10010010 → 146 − 256 = −110 → −110/8 = −13,75.
  • Un nombre qui demande plus de 3 bits après la virgule (3,5625 = 11,1001) n'est pas représentable en [5,3] → il faut un autre format, par ex. [4,4].

9. Virgule flottante

On écrit N = M × BE (M mantisse, E exposant). 27,9803 = 0,279803 × 10².

Norme IEEE 754 (principe)

  1. Signe S : 0 pour +, 1 pour −.
  2. On écrit |N| en binaire puis on le normalise : |N| = 1,xxxx × 2E. Le « 1, » n'est pas stocké (bit caché) : on ne garde que xxxx (la mantisse normalisée).
  3. L'exposant est stocké biaisé (« par excès ») : on écrit E + biais, avec biais = 2k−1 − 1 si l'exposant a k bits. L'exposant codé 0…0 est réservé (au zéro).

Exemple de codage [S,3,4] : 6,25

6,25 = (110,01)₂ = (1,1001)₂ × 2²
S = 0 ; exposant = 2 + 3 = 5 = 101 ; mantisse = 1001
→ 0 101 1001 = 01011001 = (59)₁₆

Exemple de codage IEEE 754 : −123,5

123,5 = (1111011,1)₂ = (1,1110111)₂ × 2⁶
S = 1 ; exposant = 6 + 127 = 133 = 10000101
mantisse = 1110111 complétée à 23 bits : 11101110000000000000000
→ 1 10000101 11101110000000000000000 = C2 F7 00 00

Exemple de décodage IEEE 754 : C1 18 00 00

1100 0001 0001 1000 0000 ... → 1 | 10000010 | 00110000000000000000000
signe 1 → négatif ; exposant 130 − 127 = 3 ; mantisse (1,0011)₂ = 1,1875
→ −1,1875 × 2³ = −9,5
⚠️ Précision limitée Avec 23 bits de mantisse, un float a ≈ 7 chiffres significatifs. 10¹⁴ est stocké 100000000376832 et x − 1 donne la même valeur : « 1 » est trop petit pour modifier x (TD3 machine). Et 0,1 n'est pas exact, donc y n'atteint jamais exactement 10 en ajoutant 0,1.

10. Codage des caractères (CM4)

  • Baudot (1874) : 5 bits, deux alphabets (codes 11011 et 11111 pour changer d'alphabet) → ~60 caractères. Utilisé par le Télex.
  • ASCII (1963, ISO 646) : 7 bits = 128 caractères : lettres sans accents, chiffres, ponctuation. Les 32 premiers = codes de contrôle (CR, LF, tabulation…). Un 8e bit = bit de parité ou 0. À connaître : '0' = 48 (0x30), 'A' = 65 (0x41), 'a' = 97 (0x61), espace = 32 (0x20). Minuscule = majuscule + 32.
  • ISO-8859 (fin des années 80) : extensions sur 8 bits (accents, grec, cyrillique…).
  • Unicode (années 90) : un numéro (« point de code ») pour chaque caractère de tous les alphabets. UTF-8 est une façon de stocker ces numéros, la plus utilisée depuis 2007.

11. Les fichiers en C (CM5)

La mémoire (RAM) est perdue à la fin du programme → on sauvegarde dans des fichiers. Fichier texte = caractères lisibles ; fichier binaire = octets bruts (pas lisibles directement).

#include <stdio.h>
FILE *f;
f = fopen("notes.txt", "r");          /* 1. ouvrir */
if (f == NULL) {                       /*    TOUJOURS vérifier */
    printf("Erreur d'ouverture.\n");
    return 1;
}
/* 2. lire / écrire */
fclose(f);                             /* 3. fermer */

"w"écriture : efface le contenu s'il existe, crée sinon
"a"ajout à la fin (crée si besoin)

/* Lire un fichier caractère par caractère */
int c;
while ((c = fgetc(f)) != EOF) {
    putchar(c);
}

12. Détection et correction d'erreurs (CM6)

Pendant une transmission, un bit peut changer (bruit) : 'A' = 01000001 devient 01000101 = 'E'. Idée clé : la redondance (envoyer plus de bits que le message).

  • Détecter = savoir qu'il y a une erreur ; corriger = savoir quel bit est faux et le réparer.
  • Rendement = bits du message / bits transmis. Doubler le message : rendement 50 % (mauvais).

Distance de Hamming

Nombre de bits qui diffèrent entre deux mots : d(1011101, 1001001) = 2. Si les mots du code sont à distance ≥ 2 les uns des autres, une erreur sur 1 bit donne un mot inconnu → détectée.

Bit de parité

  • Parité paire : on ajoute un bit pour que le nombre total de 1 soit pair. 1010001 (3 uns) → 10100011. (Ce bit = XOR de tous les bits.)
  • Détecte un nombre impair d'erreurs ; deux erreurs passent inaperçues. Ne corrige pas.

Parité bidimensionnelle

On range les bits en tableau, bit de parité par ligne et par colonne. Une erreur → une ligne et une colonne fausses → leur croisement localise le bit → on peut le corriger.

Somme de contrôle (checksum) et formule de Luhn

On envoie aussi une valeur calculée à partir des données (ex. somme 12+25+17+8 = 62). Utilisé par ISBN, IMEI, cartes bancaires…

Luhn (modulo 10) : de droite à gauche, poids 1, 2, 1, 2… ; on multiplie ; si un produit dépasse 9 on retire 9 ; on additionne ; valide si la somme est un multiple de 10.

Code      9  7  2  4  8  7  0  8  6
Poids     1  2  1  2  1  2  1  2  1      (en partant de la droite)
Produits  9 14  2  8  8 14  0 16  6
Chiffres  9  5  2  8  8  5  0  7  6     somme = 50 → multiple de 10 → valide

CRC (contrôle de redondance cyclique)

  • Le message est vu comme un polynôme : 1101 → x³ + x² + 1. Émetteur et récepteur se mettent d'accord sur un polynôme générateur G (ex. x³+1 = 1001 ; CRC-32 pour Ethernet, ZIP…).
  • On ajoute des 0 au message, on fait la division polynomiale avec des XOR, on envoie message + reste. Le récepteur divise à son tour : reste nul ⇒ pas d'erreur détectée.
  • Exemple du cours : m = 1001101011, G = 1001, le cours ajoute 4 zéros et trouve R = 0101 → on transmet 1001101011 0101.
Division par XOR : on aligne G sous le premier 1, on fait XOR, on recommence.

⭐ Code de Hamming 7-4 (détecte ET corrige 1 erreur)

Mot de 7 bits = 4 bits de message D + 3 bits de contrôle C placés aux positions puissances de 2 (1, 2, 4) :

position7654321
bitD3D2D1C2D0C1C0
  • C2 rend pair le groupe des positions 7, 6, 5, 4.
  • C1 rend pair le groupe 7, 6, 3, 2.
  • C0 rend pair le groupe 7, 5, 3, 1.

(Chaque position est contrôlée par les C dont le numéro apparaît dans son écriture binaire : 7 = 111 → C2, C1, C0 ; 5 = 101 → C2, C0.)

Coder 1010 : D3=1 D2=0 D1=1 D0=0
C2 = parité(1,0,1) = 0   C1 = parité(1,0,0) = 1   C0 = parité(1,1,0) = 0
→ mot de Hamming : 1 0 1 0 0 1 0 = 1010010

Recevoir 0010010 : on recalcule les 3 groupes
groupe 7,6,5,4 : 0+0+1+0 impair → erreur (1)
groupe 7,6,3,2 : 0+0+0+1 impair → erreur (1)
groupe 7,5,3,1 : 0+1+0+0 impair → erreur (1)
syndrome C2C1C0 = 111 = 7 → le bit n°7 est faux → on corrige : 1010010

Rendements : 7-4 → 57 % ; 15-11 → 73 % ; 31-26 → 83 %. Longueur totale 2ⁿ − 1 avec n bits de contrôle.
